# Indexed SM110 attention implementation

This ApxInf-owned provider combines native BF16/F32 CUTLASS FMHA with indexed
FA2 recomputation. It uses the existing dense Attention contract and is exposed
only as a Flexible candidate, never the cold fallback or a Stable implementation.
Implementation identity: provider 3, implementation 3, version 1, configuration 0.

The native correction stage flags rows whose FP32 output lies within 16 FP32
ULP of a BF16 rounding midpoint. A stable GPU compaction lists flagged queries
in ascending order per head. FA2 reads those original queries and overwrites
only their output rows. This empirical numerical safeguard is not a proof of
bitwise agreement for arbitrary inputs; independent operator and full model
quality gates remain necessary before runtime admission.

The six provider-owned buffers total 1,143,844 bytes for the supported domain:
Q=1785, Hq=Hkv=40, D=128, batch=1, K in {2665,512,257}, separate BF16 Q/K/V,
BF16 output, no mask, default scale, SM110. The execution retains Q/K/V/output.
Preparation allocates scratch and encodes kernel descriptors; enqueue performs
only asynchronous GPU operations on the caller stream. Flags/counts are reset
each invocation. No input values are read back to choose a provider.

## Generated compatibility headers

No additional vendor snapshot is imported. `build.rs` copies three canonical
headers to `OUT_DIR/attention-indexed-sm110` and applies
`native/patches/attention-indexed-sm110.patch`. Their source bytes and patch
participate in staging invalidation and the Attention build fingerprint.

retain their embedded NVIDIA BSD notices; the local FMHA snapshot is identified
above by exact source hashes rather than an unrecorded upstream revision.
Generated copies preserve all upstream copyright/license text.

The CUTLASS patch adds midpoint flags and reference-oriented row summation and
scaling, and isolates modified mainloop/load types in `indexed_collective`.
The FA2 patch changes Q loading and final O addressing through a row map; it
uses a derived parameter type in a distinct `FLASH_NAMESPACE`. Canonical vendor
headers and ordinary providers remain unchanged.

Staging was checked for exact generated bytes, unchanged canonical sources,
and idempotence. Thor compilation passed for both CUDA translation units and
the provider/registry. A linked production-kernel harness passed 12 closed-form
eager/Graph cases across all three key lengths, including 71,400 selected rows,
zero/full reset, sorted mapping, and large equal finite logits. A link-wrapped
CUDA runtime check observes three function-attribute calls per preparation and
zero during enqueue; its negative control detects the previous CUTLASS launch
wrapper resetting attributes during enqueue. The prepared launch submits
`cudaLaunchKernelExC` directly with retained parameters and cluster metadata.

The corrected backend passes 169 regression tests; the unchanged exhaustive
convolution test passed in the preceding 170-test suite. Fresh model contracts,
five VAE bitwise checks, six independent VAE reference checks, and all original
56 joint action/video checks pass. Full public acceptance and a frozen public
ABBA comparison against the normalization-suffix baseline pass; see
`doc/dreamzero.md` for measured performance and scope. These results qualify
the recorded model workload, not bitwise equality for every possible input or
a Stable numerical contract.
