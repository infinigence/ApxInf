## 新增验收能力

`expenses-tools-cny-v1` 和 `expenses-tools-usd-v1` 使用不同交易和筛选规则。
两者共享同一份原创、仅依赖 Python 标准库的计算工具。
模型需要读取规则和输入，写入筛选计划，运行固定命令，再通过 Edit 保存计算结果。
计划只包含币种、状态和类别，不接受代码或表达式。
工具按整数分计算，支持退款、零金额、带逗号的 CSV 字段，并保留原始交易顺序。

工具只读取固定文件并输出收据，不写入最终结果。
收据绑定交易、规则、计划和计算工具的字节摘要。
验收器独立检查真实调用顺序、成功工具结果、收据、模型写入的文件和预先固定的字面量答案。
失败工具调用、未知文件路径、缺少计算、重复最终结果和不确定 JSON 数值均不能通过。
类别顺序不影响筛选；交易 ID 顺序必须与 CSV 一致。
该机制依赖可信捕获和无外部写入，不构成操作系统沙箱。

这些文件及额度上限定义计算工具边界，不代表模型容量。
CPU 测试验证工具与验收器，不能代替模型完成任务。

## 实际 M4 与 Claude Code

使用 Apple M4，模型为 MiniCPM5-2B，revision 为 `f97400052a43d642bbc6e9975e2397e3ae6a6b52`。

上下文上限为 16384，输出上限为 4096，客户端截止时间为 300 秒。

运行前固定两套案例、三次重复、顺序和停止条件。
顺序为 CNY、USD、CNY、USD、CNY、USD，没有修改提示或重试。

## 后续工作目录修复

上述六次运行暴露了测试环境的目录归属问题。
客户端的工作目录同时包含案例文件、配置、stdout、stderr 和进程记录。
六次原始流均成功读取了自己的 stdout，返回内容分别约为 3.9 万字符。
这证明了证据文件暴露和额外对话输入，尚未分离其对模型最终失败的影响。

修复前新增的回归测试运行真实 Python 子进程，并保留实际任务准备、捕获及报告路径。
HTTP 发现和指标使用本地替身，不启动模型。
子进程退出零，工具清单验证通过，目录断言精确报告四项额外内容。

```text
AssertionError: Items in the first set but not the second:
'client-config'
'client.process.json'
'client.stdout.jsonl'
'client.stderr.txt'
```

客户端配置、捕获日志和进程记录位于其外层，由各自所有者保存。
所有维护中的捕获与环境调用者一次迁移，不保留旧目录参数分支。

报告新增 `environment_revision=task-workspace-v2` 和 `attempt_directory`。
原有 `directory` 指向实际子进程工作目录，产物校验使用同一个路径。
进程标记仍保持单层 `tasks/*/client.process.json` 布局，原观察器可以继续验证所属进程。
原捕获循环、实时写入、截止时间、取消、管道排空和退出清理保持原行为。
原任务提示、CSV、规则、计算工具、字面量答案、严格调用顺序和模型预算没有修改。
该目录调整不限制父路径访问，不构成操作系统沙箱。
