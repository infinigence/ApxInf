## 新增验收能力

`expenses-tools-cny-v1` 和 `expenses-tools-usd-v1` 使用不同交易和筛选规则。
两者共享同一份原创、仅依赖 Python 标准库的计算工具。
模型需要读取规则和输入，写入筛选计划，运行固定命令，再通过 Edit 保存计算结果。
计划只包含币种、状态和类别，不接受代码或表达式。
工具按整数分计算，支持退款、零金额、带逗号的 CSV 字段，并保留原始交易顺序。

工具只读取固定文件并输出收据，不写入最终结果。
收据绑定交易、规则、计划和计算工具的字节摘要。
验收器独立检查真实调用顺序、成功工具结果、收据、模型写入的文件和预先固定的字面量答案。
失败工具调用、未知文件路径、缺少计算、重复最终结果和不确定 JSON 数值均不能通过。
类别顺序不影响筛选；交易 ID 顺序必须与 CSV 一致。
该机制依赖可信捕获和无外部写入，不构成操作系统沙箱。

这些文件及额度上限定义计算工具边界，不代表模型容量。
CPU 测试验证工具与验收器，不能代替模型完成任务。

## 实际 M4 与 Claude Code

使用 Apple M4，模型为 MiniCPM5-2B，revision 为 `f97400052a43d642bbc6e9975e2397e3ae6a6b52`。
选择原生 `metal_minicpm5`、BF16 compiled、MLX 0.31.2 和关闭思考的配置。
Claude Code 为 2.1.289，命令请求 `--max-turns 8`。
上下文上限为 16384，输出上限为 4096，客户端截止时间为 300 秒。
服务请求截止时间为 180 秒，内存预算为 8 GiB，序列预留为 3 GiB。

运行前固定两套案例、三次重复、顺序和停止条件。
顺序为 CNY、USD、CNY、USD、CNY、USD，没有修改提示或重试。
本次使用默认 macOS 压力准入，能够就绪，因此没有再运行关闭准入的诊断变体。

| 实际任务 | 通过 | 共同失败表现 |
| --- | --- | --- |
| CNY，三次重复 | 0/3 | 先调用不允许的 `ls -la`，未形成有效计算收据 |
| USD，三次重复 | 0/3 | 先调用不允许的 `ls -la`，未形成有效计算收据 |

六次客户端均退出 1，最终返回 `Prompt is too long`。
模型随后读取了任务外的捕获日志等文件，没有完成规定的计算与保存流程。
六次记录均保留原输入，没有有效计算收据，也没有合格最终报销文件。
客户端最终事件虽然标为 `subtype=success`，但 `is_error=true`，验收器仍判失败。
实际事件报告 `num_turns=11`，因此不能把请求的八轮参数描述为已验证的硬上限。

服务完成 18 次生成和 6 次计数请求，全部使用同一个 worker epoch。
每例前后的活跃请求、排队和预留容量均为零，worker 故障增量均为零。
18 条生成结算记录中的最大实际输入为 2338 token，不是 16K 长上下文验收。
压力采样为 862 次 normal、7 次 warning，没有 critical 或 unknown。
本次就绪结果不证明所有压力变化下均能准入，也不能用于认定 Clef 默认准入通过。

服务退出零，任务 runner 退出一。
观察线程停止，所属进程组为空，已启动进程组为空，设备锁可独立重新获取。
选中的服务、worker、动态库和所列源文件在运行前后摘要一致。
客户端可执行文件仅记录运行前摘要，未作运行后复查，运行期间未更新该文件。
