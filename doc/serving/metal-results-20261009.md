# M4 serving 参数矩阵实测：2026-10-09

本文记录历史构建的参数实验，不代表当前 PR 最终提交的实机验收。原始 matrix 结果未随 PR 上传；下文结果链接仅用于定位本地证据，不能作为可移植附件。

九组配置完成了 **144/144 次测量请求和 18/18 次预热请求**。运行过程没有请求错误、模型工件变化或运行时变化。所有自有实验进程均已退出。

**跨预填充块的输出一致性门槛没有通过。** 驱动按设计返回退出码 `2`，保留完整结果。相同预填充块下，输出批量 1、4、8 的可见输出哈希逐请求一致。不同预填充块之间，各有两条长输入出现输出差异。此次结果不支持改变默认配置，也不代表 Metal kernel 加速。

## 环境与口径

- Apple M4，`Mac16,10`，16 GiB 统一内存，macOS 27.0.1。
- 本地 Qwen3.5-2B 工件，快照 `15852e8c16360a2fea060d615a32b45270f8a8fc`。
- Python 3.14.3、MLX 0.32.1、MLX-LM 0.31.3。完整包版本与工件 SHA-256 见每组 `ready.json`。
- 每组独立启动一个常驻模型，先预热一条长输入和一条短输入，再串行测量 16 次请求。
- 每组短输入 12 条，32–33 个输入 token；长输入 4 条，1174–1175 个输入 token。每次实际输出均为 32 个 token。
- 测量通过 Anthropic Messages 流式 HTTP 接口，客户端并发为 1。父进程持有 Metal 协作锁，九组顺序运行。
- 服务二进制 SHA-256：`fc7f81c3862555bc62efde006571968fddcef6176ded17a7d35ce26ff474658b`。驱动、请求脚本与模型执行身份见原始记录。

TTFT 从客户端发起请求计时，到首个非空内容增量为止。输出间隔指 HTTP 内容事件间隔，不是模型 token 间隔。吞吐为完整测量阶段的输出 token 数除以耗时，包含预填充成本。

## 输出一致性

输入索引从 0 开始。长输入索引为 `0, 4, 8, 12`，其余均为短输入。

| 比较 | 不同的请求索引 | 结论 |
| --- | --- | --- |
| 固定 64，批量 1/4/8 | 无 | 16/16 可见输出一致 |
| 固定 256，批量 1/4/8 | 无 | 16/16 可见输出一致 |
| 固定 1024，批量 1/4/8 | 无 | 16/16 可见输出一致 |
| 64 与 256 | `0, 4` | 两条长输入不同 |
| 64 与 1024 | `4, 8` | 两条长输入不同 |
| 256 与 1024 | `0, 8` | 两条长输入不同 |

这些比较只验证 HTTP 可见文本的 SHA-256。请求脚本没有保存模型 token ID、logits 或完整输出文本，不能据此证明 token 一致性，也不能判断差异的根因与质量优劣。预填充执行次序的数值影响是后续待验证假设，不是本次结论。

九组服务都通过自有进程组的 `SIGINT` 清理，网关退出码均为 0。驱动逐组等待清理完成。结束后的独立进程检查确认九个进程组均无残留。该检查只涉及矩阵创建的进程，没有终止父进程持锁服务或其他进程。

## 能支持的判断

1. 输出批量将每请求内容事件数的中位数从 32 降至 9、5，同时把可见输出间隔从约 42 ms 拉长到约 165 ms、330 ms。首个 token 单独发送，因此短输入 TTFT 没有随批量成倍增加。吞吐变化小且不单调，不能宣称收益成立。
2. 在输出批量 1 下，64→256 的长输入 TTFT 观测值下降约 11.6%，MLX 峰值增加约 0.11 GiB。但输出也发生变化，尚不满足直接替换的条件。
3. 256→1024 的长输入 TTFT 只再下降约 1%，MLX 峰值增加约 0.41 GiB。小样本和运行顺序不足以证明这点延迟差异可重复。
4. 保留默认 `256/1`。后续先定位长输入的输出差异，再用平衡顺序复测候选配置。输出合并若继续探索，应加入可见延迟预算，不宜只增大批量。

## 限制与混杂因素

系统 `vm.swapusage` 的已用值从首次测量前的 `3606.88M` 增至最后清理后的 `5105.88M`。其中 `256/4` 前后从 `3749.69M` 跳至 `5265.88M`。这是整机观测，无法归因于单个模型或请求，也无法宣称本轮无 swap 干扰。

九组只运行一轮，顺序固定。每组只有四条约 1.2K token 长输入，没有完成原方案的 2K/8K 长输入、取消延迟、慢消费者或并发公平性矩阵。未采集 GPU kernel 计数器、CPU 利用率或逐 token ID。原始报告中的 p95 只作探索记录，不支持尾延迟保证。本轮是 serving 参数实验，不是 kernel 优化性能证明。
