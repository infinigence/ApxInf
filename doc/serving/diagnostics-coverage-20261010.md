# 诊断输出隔离与内存覆盖检查

日期：2026-10-10。范围：串行 serving 的故障恢复和离线校准证据。

本轮修复 stderr 故障阻断服务生命周期的问题，并新增内存校准覆盖检查。没有运行 GPU、调整内存预算或开启批处理。

## 诊断输出的问题与修复

原协调器在 worker fence、轮换和请求结算中同步执行 `eprintln!`。关闭 stderr 管道可能触发 panic，写满管道会阻塞调用线程。fence 的打印发生在撤销可用性和回收进程之前，因此会阻断故障恢复。

原 CLI 返回 `Result`，Rust 在错误退出时也会同步打印 stderr。独立进程实验填满 65536 字节的 stderr 管道，再传入不存在的模型路径。旧 release 在两秒内不能退出，测试父进程随后终止并回收它。这个实验不加载模型。

现在诊断输出使用一个进程级写线程和容量为 256 条的队列，每条最多 4096 字节。调用方只尝试入队。满队列丢弃新记录，超长记录整条丢弃，写入失败后停止该输出并记录丢失指标。格式化缓冲也受字节上限约束。

worker stderr 改为独立管道，异步读取任务按 512 字节读取，并在读取之间让出执行机会。它持续排空管道，不等待诊断记录写出。worker 实例销毁时取消这个读取任务，避免等待其他进程长期持有的管道。

CLI 使用显式退出码。启动错误和参数错误使用同一诊断出口，帮助信息仍写 stdout。退出时最多额外等待 100 毫秒交付诊断记录，不等待被阻塞的写线程。这个上限只约束诊断收尾，不代表整个进程启动或退出的耗时。

诊断指标采用固定名称与标签，涵盖写出记录、满队列、超长记录、不可用出口、写错误和 worker stderr 读取错误。指标描述整个进程，包括 worker 轮换。线程可用不代表日志正在写出，计数也不涵盖未读取字节或进程退出后无法记账的记录。

诊断是尽力交付的运行记录。请求结果、readiness 和资源结算以对应状态及指标为准。

## 内存覆盖检查

新增 `benchmarks/serving/memory_coverage.py`。它只读取现有 `calibration.json`、`process.json` 和 `samples.jsonl`，不导入 MLX，也不改写原始文件。

分析结果分别报告计划、执行、生成观测和实际达到的边界。提前 EOS 不等于达到输出上限。停止场景单独保留，不冒充完整输出形状。报告保留物理 cache offset、未知值、清理和进程回收证据，以及缺失的输入和输出区间。

峰值按 `run_id` 与 `peak_epoch` 归属。`before_request` 或零输出请求读到前次峰值时，不会把该峰值分配给新请求。分析器不叠加 allocator 峰值、当前活跃内存和逻辑缓存载荷。

校验覆盖 JSON 重复键、摘要、记录顺序、输入身份、阶段顺序、压力阻断和 epoch 转移。独立复审发现过两类错误接受路径：阻断启动后的执行证据，以及不合法的终态／清理 epoch。实现已修复，五个复现变体均被拒绝。

旧实测目录 `/private/tmp/apxinf-serving-calibration-8JtDPj/subset` 的离线回放结果如下：

| 项目 | 结果 |
| --- | --- |
| 证据内部一致性 | valid |
| 计划 case | 11 |
| 执行 case | 0 |
| 生成观测 case | 0 |
| 达到目标的 case | 0 |
| 唯一峰值区间 | 加载 epoch 0，3763655400 字节 |
| 计划未包含的输出 allowance | 2–7、9–2048 |
| 内存预算批准 | false |

实际达到的形状仍为空，包括计划中的 allowance。上述缺失 allowance 只是计划缺口，不能理解为其余 allowance 已经测过。

`valid` 只表示记录通过一致性检查。即使所有计划 case 完成，也不建立任意输入、执行重叠或主机条件下的内存上界。

诊断专项覆盖关闭和写满 stderr 时的 worker fence、连续请求结算与轮换。两个附加场景排空 1050000 字节无换行数据，其中包含无效 UTF-8 和 NUL。它们检查 stdout 完成、进程回收、日志丢失指标和有界退出。

测试过程中修正了 fence probe 对 EOF 错误文字的过窄断言。probe 的 panic 信息改写 stdout，避免测试断言本身被 stderr 故障阻塞。初始 RED 与最终 GREEN 的日志均保留。

首次 Python 全套运行受沙箱限制，不能绑定回环端口或执行进程检查。授权环境中的重跑通过，首次失败日志仍保留。测试的自有子进程均有回收路径。

## 剩余验收

本轮不增加生成内存实测，也不建立 TTFT、吞吐或模型质量的新结论。仍需在正常主机压力下取得输入、输出、停止和重复请求的生成证据，再设计和验证内存估算。P1b exact sessions、批处理及缓存能力继续遵守既有阶段门。
