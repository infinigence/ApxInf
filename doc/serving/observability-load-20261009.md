# Serving 阶段观测与固定到达率验证

日期：2026-10-09。本轮在[生命周期加固](lifecycle-hardening-20261009.md)之后继续改进 serving。交付范围是阶段指标、submit 写入期间的公共 deadline，以及可暴露过载的 HTTP 负载器。worker 协议仍为 `apxinf-worker/2.0`，没有新增运行时依赖。

## 实现变化

- 新增九类固定桶直方图，区分排队、准备、worker 首 token、首个 worker 输出事件、公共输出就绪、输出事件间隔及终态结算。
- 新增按 `generate`／`count_tokens` 分类的请求结果计数和 `cleanup_pending`。旧、新结果计数使用同一导出快照，保持逐状态聚合一致。
- 公共输出就绪指非空文本或完整工具调用成功进入结果通道，不表示客户端已收到内容。事件聚合间隔不等于逐 token ITL。
- 排队取消和过期也产生等待及请求耗时样本。缺失首输出不填零；进程回收未确认时不产生结算样本。
- submit 写入期间检查公共 deadline 和取消。公共终态后保留原写入，不重发部分帧；随后仅消费协议结算，迟到 accepted／内容／成功结果不对外发布。
- HTTP 基准新增固定到达率与客户端 in-flight 上限。容量不足时记录明确丢弃，不把等待任务隐藏在 executor 队列中。
- HTTP 请求使用绝对 deadline。持续心跳、部分 SSE 行、慢响应头及发送阻塞都不能无限延长请求。
- 基准分别报告请求发起和计划到达起算的延迟与 goodput。warmup 失败保留证据，并使退出码为 1。

指标定义和桶边界见[接口规范](contracts-v0.1.md#observability-contract)。负载参数及样本字段见[基准说明](../../benchmarks/serving/README.md)。

## 测得的排队行为

闭环先执行两次 warmup，再分别测并发 1 和 2，每组八次请求。p50 为中位数，p95 采用 nearest rank；八个样本的 p95 等于样本最大值，不能建立产品尾延迟 SLO。

| 客户端并发 | 完成 | 输出 tokens/s | 客户端首内容 p50 | 客户端首内容 p95 | E2E p50 |
| --- | --- | --- | --- | --- | --- |
| 1 | 8/8 | 17.873 | 0.219 秒 | 1.218 秒 | 1.548 秒 |
| 2 | 8/8 | 17.829 | 2.258 秒 | 2.773 秒 | 3.586 秒 |

同一八条输入在两组中的输出文本哈希全部一致。这仅检查相同执行 profile 下的重复输出，不代表完整任务质量验收。该实验没有设置优化前版本的交错基线，因此不声称本轮提高了推理吞吐。

固定到达率检查设置为每秒 2 次、12 次计划请求、最多 4 次客户端 in-flight。实际发送并完成 6 次，另外 6 次记录为 `client_capacity_drop`。负载器按设计返回 1，保留全部失败样本；这 6 次没有到达服务端，不应计入服务端失败总数。

该组含 drain 的总时间为 10.246 秒。已发送请求的首内容均值为 3.334 秒，E2E 均值为 4.646 秒。测试阈值为首内容 3 秒、E2E 15 秒，仅 2/12 次计划请求达标，goodput 为 0.195 请求/秒。计划到达起算也为 2/12；平均 dispatch 延迟为 6.48 毫秒。这些阈值用于演示测量，不是已承诺的产品 SLO。

服务端直方图在该固定到达率阶段的六次生成样本显示：

| 阶段 | 平均耗时 |
| --- | --- |
| 排队 | 2.937 秒 |
| 准备输入 | 1.024 毫秒 |
| worker 本地首 token | 0.393 秒 |
| 入队至首个 worker 输出事件 | 3.333 秒 |
| 相邻 worker 输出事件 | 42.31 毫秒 |

这些观测支持下一步优先处理串行执行下的等待问题。准备输入不是本次负载的主要耗时。阶段可能重叠，不能把表内所有行相加。

## 资源与测量限制

断连取消和满队列检查均通过。最终生成请求计数为完成 26、取消 18，token counting 完成 2；失败、过期及 worker fault 均为 0。旧、新结果计数一致。active、queued、reserved bytes 和两类 cleanup_pending 全部归零。

MLX allocator 峰值为 4,038,199,082 字节，约 3.761 GiB。这不是 RSS 或整机物理内存。测量前 swap 使用约 4749 MiB，结束时约 6252 MiB；期间 Swapouts 增加 110040 页，页大小为 16384 字节。系统还运行其他应用，不能将全部变化归因于本服务，也不能宣称无分页干扰。

只向已核验的本次服务 PID 83870 发送 SIGINT。服务等待 worker 83871 回收后退出；父 launcher 返回 0，进程组剩余成员为空，测量锁随之释放。

## 后续阶段门

本轮未完成按请求长度的内存估计、系统压力反馈、固定产品 SLO、exact append 或连续批处理。固定 1 GiB sequence reservation 仍是部署估计。

下一步先明确模型状态、临时工作区和系统余量的计费边界，建立受支持模型的请求内存准入，再校准延迟及质量目标。之后才能打开批处理或自动缓存的性能验收门。实现顺序仍由[实施计划](implementation-plan.md)约束，持续优化目标保持进行中。
