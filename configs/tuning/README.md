# GEMM tuning databases

Each hardware compatibility domain owns one shared `tactics.json` and one
diagnostic `tuning_report.json`. Records are keyed by the physical GEMM
contract, not by model, layer, or executor name.

```text
configs/tuning/<vendor>/<device-family>-sm<version>/cuda<major.minor>-cublas<major.minor>/
├── tactics.json
├── tuning_report.json
└── <exact-key-hash>.recipe
```

At runtime an exact key wins over a bucket key. Missing records use the safe
provider default in inference mode. With autotuning explicitly enabled, a real
request validates and benchmarks provider candidates, atomically merges the
exact winner into the hardware database, and records candidate measurements in
the report.

Legacy CUDA can also resolve older hardware-only directories when their records
are library-compatible. `kernel_build_id` and the full device name never reject
the whole legacy database. Provider
`implementation_version` (plus the relevant CUDA/cuBLAS compatibility for that
provider) controls record-local invalidation.

## MUSA

MUSA keeps its databases under `musa/`, with the device name lowercased and the
MP generation in the directory name:

```text
configs/tuning/musa/<device-name-lowercased>-mp<mp>/
├── tactics.json
├── tuning_report.json
└── musa<major.minor>-mublaslt<major.minor>/
```

A clean checkout has no `configs/tuning/musa` and
every shape uses the safe default; the shipped-database test validates a
database only when one is present.

## cuda-new recipes

cuda-new GEMM and Attention default to the hardware/toolkit directory above,
independently of whether `tactics.json` exists. Each `.recipe` contains one exact
operator key and its selected implementation/configuration, not model weights or
a whole-model plan. Different models can share a record only when their exact
operator keys match. Build/device/library/shape/policy compatibility is validated
by the key; legacy JSON records are not imported.

PI05 `LoadOptions.autotune` and `pi05_bench --autotune` enable benchmarking on a
recipe miss during preparation or first execution, then persist the winner.
Without autotune, existing recipes are reused and misses use a safe fallback;
creating a cache directory alone does not tune anything. Explicit `cache_dir`
overrides the default; an empty string disables disk persistence. Paths are
relative to the process working directory unless explicitly absolute. Generated
recipes are ignored by Git, and writes require a writable directory.

## AMD / HIP GEMM recipes

`apxinf-hip` chooses between hipBLAS and hipBLASLt per GEMM shape. Neither wins
everywhere: measured over GR00T N1.7's 26 shapes on gfx1151, hipBLASLt is
1.05x–3.71x faster on the 13 shapes below the roofline ridge point and
0.58x–0.90x *slower* on the 5 above it, and no closed form separates the eight
near the ridge. The choice is therefore measured, not derived.

```text
configs/tuning/amd/<gfx-arch>/rocm<major.minor>-hipblaslt<version>/gemm.recipe
```

One line per shape: `bf16 M K N provider [tactic]`, where the tactic is a
serialized `hipblasLtMatmulAlgo_t`. hipBLASLt's header states that a recorded
solution cannot be used across library versions, so the version is in the
directory name — an upgraded host misses and re-tunes rather than reading a
file that no longer means what it says. The file also carries a
`# measured-on <arch> rocm<..> hipblaslt<..>` line, and a mismatch is refused
whole.

| Situation | Behaviour |
| --- | --- |
| No recipe at the path | hipBLAS everywhere, as before |
| Recipe present | Its choices are used; shapes it does not list stay on hipBLAS |
| Recipe present, header mismatched | Refused with a message; hipBLAS everywhere |
| `APXINF_HIP_GEMM_AUTOTUNE=1` | Shapes the recipe misses are measured on first use and written back |

A recipe is honoured without a further flag because its path already states
which device and libraries it was measured on, the header is checked against
them, and every tactic is trial-launched before it is trusted. Tuning once
makes later loads faster with nothing to remember.

Autotune measures **cache-cold**, streaming a ring of weight copies past the
32 MB MALL. Timing one weight matrix back to back leaves it cache-resident,
which is not the state a real inference sees — the DiT alone streams 576 MB of
weights per flow step. The difference changes the answer: 3 of 12 shapes pick a
different provider when measured warm.

Tuning GR00T's 29 shapes costs about 5 s of load time, once.

Overrides, for A/B measurement rather than deployment:

| Variable | Effect |
| --- | --- |
| `APXINF_HIP_GEMM_PROVIDER` | `hipblas`, `lt`, or `auto` |
| `APXINF_HIP_GEMM_TACTICS` | Read and write this recipe instead of the default path |
| `APXINF_HIP_GEMM_AUTOTUNE` | `1` to measure on a recipe miss |

`.recipe` files are ignored by Git, here as on the CUDA side: they are caches
keyed to one machine and one library build, regenerated by autotune rather than
distributed.
